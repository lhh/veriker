# V-Kernel TypedCheck Reason Codes

These are the reason codes emitted by V-Kernel `audit_bundle` TypedCheck plugins.

**WHAT THIS FILE COVERS, corrected 2026-08-30.** It previously opened by calling
itself *canonical*, while documenting 0 of the 108 pilot-local codes under
`examples/` and omitting 16 of the codes emitted by `audit_bundle/` itself. It
covers the DISTRIBUTION codes only, and a ratchet test
(`tests/test_reason_codes_doc_ratchet.py`) now fails when a code emitted under
`audit_bundle/` is missing here, so the gap cannot silently reopen. Codes
emitted by a pilot's own plugins under `examples/` are not ratcheted here.

## The canonical re-derivation vocabulary

Four events are UNIVERSAL to every Axis-2 re-derivation. They are emitted under
these names by every check, in every domain — a domain prefix on any of them
says nothing the `check_name` on the verdict face does not already say. 156
domain-prefixed spellings across 55 pilots were collapsed onto these on
2026-08-30; `audit_bundle/rederivation/reason_codes.py` is the definition.
Nothing currently REFUSES a reintroduced domain prefix -- `classify()` names one
when asked, and no caller in the verify path asks.

| Code | Meaning |
|---|---|
| `RE_DERIVED` | The recompute ran and agreed with the producer's claim. |
| `RE_DERIVATION_MISMATCH` | The recompute ran and DISAGREED. A REJECT. |
| `RE_DERIVATION_TIMEOUT` | The recompute did not finish in the budget. Could-not-conclude, never a pass. |
| `RE_DERIVATION_NOT_COMPARED` | The pack exited cleanly having compared NOTHING. Carries `incomplete=True`: neither REJECT nor OK. |

**Whether a code reaches the verdict face depends on WHICH PATH emitted it.**
There are two, and they behave differently — stated here because reading only
the paragraph that used to be in this slot would leave you believing codes
never survive, which is false for half the fleet.

* **Spec-pinned dispatch — the code SURVIVES VERBATIM.** `verifier.py` copies
  it straight through (`reason_code=df.reason_code`), so a machine reading
  `--verdict-out verdict.json` sees the real code. `event_log_replay_minimal`'s
  battery asserts the exact reason-code *set* (`== {"RE_DERIVATION_MISMATCH"}`)
  and passes, which is the executable proof of this half.
* **Typed-check plugins — the code is PROPAGATED (since 2026-08-30).**
  `_step_typed_check_plugins` puts the plugin's own
  `PluginResult.reason_code` on the verdict face verbatim, alongside
  `check_name` (`typed_check_plugins:<plugin_id>`) and `detail`. Two arms stay
  deliberately generic and still record `reason_code="plugin_failed"`:
  * the plugin **raised** `PluginFailed` — there is no result object, so there
    is no code to propagate;
  * the check was **declared but never wired** — `manifest.typed_checks` names
    a plugin no `BundleVerifier` instance registers, so no check ran.

  A failing result whose own `reason_code` is empty or the `"PASS"` sentinel is
  malformed and also falls back to `plugin_failed`, rather than printing `PASS`
  as a failure's reason.

  Consequence for test authors: matching `check_name` ALONE is a tautology —
  the declared-but-unwired arm fails closed under the *same* `check_name`, so
  such an assertion passes with the plugin deleted. Require the detail's
  `"reported failure"` marker too (see `_check_ran_and_failed` in the pilot
  batteries), or assert on the propagated code.

The discard this replaced was not a recent regression: `plugin.py` gave
`PluginResult` a `reason_code` field and `verifier.py` was written to ignore
it, both on 2026-04-30. The original code converted a failing plugin into an
exception carrying only text, so there was nothing but a string to label —
accurate at the time. The exception was long gone and the value sat in scope
beside the line that overwrote it.

## v0.3 → v0.4 cross-host reason-code migration map

Per the deprecate-with-alias rule (never silent re-mean; never delete a published code). Third-party verifiers pinned to the v0.3 contract use this map:

| v0.3 code | v0.4 disposition |
|---|---|
| `CROSS_HOST_COSE_AUTH_RESERVED_FOR_V0_4` | **DEPRECATED, emit-never alias.** Cross-org COSE_Sign1 is now implemented. ## Spec-pinned dispatch codes (`audit_bundle/rederivation/dispatch.py`)

Added 2026-08-30. These fifteen were emitted by the shipped verifier and
documented nowhere, and the ratchet on this file was green over every one of
them: `dispatch.py` builds each failure POSITIONALLY —
`DispatchFailure(check_name, "CODE", detail)` — which neither the
`reason_code="LIT"` regex nor the collapsible-constant sweep could see. The
ratchet now introspects the dataclass field order and reads the positional
argument, so this class cannot reopen.

Every condition below is derived from its emitting site, not from the code's
name. All of them are fail-closed refusals on the `spec_pinned_dispatch` check
(the last is its own `spec_pinned_dispatch:cardinality`).

| Code | Fires when |
|---|---|
| `OUTPUT_ENTRY_MALFORMED` | A `manifest.outputs` entry is not an object, or its `output_id` is not a non-empty string. |
| `OUTPUT_ID_UNSAFE` | `output_id` fails the safe-filename grammar `[A-Za-z0-9][A-Za-z0-9._:-]{0,249}` (alphabet AND length: a 251-char id reached `is_file()` and escaped as an ENAMETOOLONG crash that outranked every REJECT already collected — red team 2026-09-01), or a claimed-value path resolves outside `outputs/`. The id is interpolated into a path, so this refuses the read rather than sanitising it. |
| `WORK_SET_VIOLATION` | The bundle did not deliver exactly the auditor's WORK-SET (`BundleVerifier(work_set=...)`): a named `output_id` is missing, an `output_id` the auditor never named is present, or one is declared more than once. An exact multiset bijection over `manifest.outputs` taken as a list, checked BEFORE the empty-outputs early return, so total omission of the declaration is refused too. A REJECT: the artifact did not deliver what was asked. Check name `spec_pinned_dispatch:work_set`. |
| `WORK_SET_CHECK_ERROR` | The verifier could not APPLY its own work-set — the held set no longer re-derives under its `universe_sha`, or the check crashed. Carried in `detail` under `VERIFIER_INCOMPLETE` (could-not-conclude): the verifier's incapacity, never evidence against the artifact. |
| `ROLE_POLICY_VIOLATION` | The auditor's work-set pins a type for this `output_id` and the bundle claims a different one — a type substitution the auditor did not license. (The per-output pin that predates the work-set keeps its code.) |
| `UNKNOWN_TYPE` | The anchored spec cannot resolve the declared `type_key` to a binding. |
| `PINNED_INPUT_UNSAFE` | An auditor-pinned input path resolves outside the bundle root. The read is refused, not attempted. |
| `PINNED_INPUT_MISSING` | An auditor-pinned input is absent from the bundle (§4a.7 fail-closed). |
| `PINNED_INPUT_MISMATCH` | An auditor-pinned input is present but its SHA-256 differs from the one the anchored spec requires. |
| `CLAIMED_VALUE_MISSING` | No `outputs/<output_id>.json` claimed-value file exists for a declared output. |
| `MALFORMED_PRIMITIVE_REF` | A `Binding`'s primitive reference will not parse. Belt-and-braces: `parse_spec` refuses these at load, so reaching here means a `Binding` was constructed outside the loader. |
| `RECOMPUTE_BIND_ERROR` | Binding `primitive.recompute` raised. The attribute is bound ONCE into a local and that same object is both hashed and invoked — a second `getattr` let a `property` hand honest code to the hasher and hostile code to the caller, measured as a clean verdict whose `digest_status` said "matched" for a file whose code never ran. |
| `RECOMPUTE_ERROR` | The bound primitive raised while recomputing. Any primitive error is fail-closed. |
| `NON_FINITE_VALUE` | A NaN or infinity appears in the recomputed value or in the producer's claimed value. Checked on BOTH sides. |
| `UNKNOWN_COMPARATOR_KIND` | `binding.comparator_kind` does not resolve, or carries a parameter the comparator does not know. |
| `COMPARATOR_ERROR` | The comparator itself raised. Wrapped so a comparator fault cannot escape as a pass. |
| `CARDINALITY_VIOLATION` | The dispatch loop produced a different number of results than there were declared outputs — one result per declared output is the invariant (§4a.8). This is the guard against an output being silently skipped. |

Two further paths emit codes that are NOT literals and so cannot be ratcheted
from source: `dispatch.py` propagates `type(exc).__name__` for `SpecBindingError`
subclasses, and `exc.reason_code` for `PrimitiveRefViolation` (whose values are
defined in `primitive_ref.py`). They are named here so the gap is disclosed
rather than merely uncovered.
