# Threat model — spec-pinned type dispatch (as-built)

**Scope:** the `audit_bundle/rederivation/` re-derivation subset of the verifier
— spec-pinned, auditor-anchored, recompute-then-compare dispatch over
`manifest.outputs`. This is the **as-built** companion to the spec-pinned
dispatch architecture design §4/§4a. It is updated **in lockstep** with the
substrate (this file lands in the
same commit as the code it describes — a stale threat model is worse than none).

**Trust frame:** the verifier does **not** trust the producer. The producer
authors the manifest (output `type` claims + `conforms_to`) and ships the bundle
(inputs, claimed outputs, spec copies). The **auditor** supplies, at
`BundleVerifier` construction and never via the manifest: a `SpecAnchor`
(`spec_id -> required SHA`) and an optional **work-set**
(`audit_bundle.work_set.WorkSet`: the complete multiset of `output_id`s the
bundle must deliver, each pinned to its required type, as a closed universe
with a verifier-held `universe_sha`; row 4b). Recompute primitives + comparator kinds are
verifier-side code, registry-resident, never bundle-supplied — either shipped
in the distribution or loaded from AUDITOR-HELD kit modules
(`load_primitive_kit` / CLI `--primitives`, row 18). "Never bundle-supplied" is
enforced by two guards, not one: a kit ENTRY inside the bundle is refused, AND
dispatch refuses any RESOLVED primitive whose source resolves inside the
bundle (`PRIMITIVE_SOURCE_INSIDE_BUNDLE`) — the latter catches a kit that
imported producer code out of the bundle. A kit is otherwise operator-trusted
code (a hostile kit is arbitrary code, out of scope); the verdict face records
each resolved primitive's code location (`primitive_provenance`) as a
best-effort, honest-kit disclosure, not a defense against forgery.

## Engagement / inert boundary

The dispatch step is **inert** unless `manifest.outputs` is non-empty (0/56
baseline manifests carry it, so every legacy bundle is unaffected and needs no
anchor). When it engages it **strictly supersedes** legacy name-dispatch for the
covered outputs and AND-aggregates into the same failure list — never `any()`
across the two paths (§4a.7). Aggregation is `all(no failures)`; a cardinality
guard asserts one evaluated result per declared output so `all([])` can never
read `True` on an empty/skipped set (§4a.8).

## Invariant — method selection is auditor-side (D2)

> **Every input that determines WHICH CODE RUNS comes from the auditor's side.
> The bundle contributes nothing to that decision — not a path, not a name, not
> a hint, not a fallback.**

Approved as written 2026-08-29 (method-distribution decision D2). The internal
design-doc pointer that stood here was a shipping-file breadcrumb the export
would have had to scrub; the decision it named is recorded above, which is what
a reader of this file needs. It is written HERE because it was enforced in-band (rows 6, 14, 15, 18)
and procedurally out-of-band, but stated nowhere — and the loss mode is not a
bad decision. It is a reasonable-sounding convenience feature added later by
someone who was not part of this design.

**Rejected by construction. Each of these looks like a UX improvement:**

1. *the bundle declares which kit it needs, so verification is one command;*
2. *the manifest carries a registry URL, a kit hint, or a method pointer;*
3. *fall back to the bundle's own spec when no anchor is supplied;*
4. *auto-resolve an unknown `primitive_id` from a registry by name.*

The last is the subtle one. Name-based auto-resolution *looks* auditor-side, but
the NAME ORIGINATES IN THE SPEC — so if the spec is ever taken from the bundle
(rows 14, 15), the loop closes with nobody noticing. This is why row 18's kit
loader takes a path from the operator's argv and never from the artifact, and
why an unregistered `primitive_id` is `UNKNOWN_PRIMITIVE` rather than a lookup.

**Reach of this document, stated so row 20 is not read as coverage.** These rows
govern `audit_bundle/rederivation/`. Row 20 states a doctrine that is ENFORCED
here (spec parse refuses a malformed ref rather than demoting it;
`CLAIMED_VALUE_MALFORMED`; `MalformedSpec` at load) and is NOT enforced by this
document in `audit_bundle/extensions/` or `audit_bundle/plugins/`, where the
measured C18 instance lives. A doctrine row is not a guard. Where the rule is
unenforced, say so rather than letting the row read as though it reaches.

**Row 20 now has a mechanical guard, and its reach is narrower than the
doctrine.** `audit_bundle/_degradation.py` asserts the row as a metamorphic
relation over a degradation ladder — MR-1: no PRESENT rung may be softer than
any LESS-DEGRADED present rung, along the whole ordered ladder; MR-2: an ABSENT
rung that passes while a less-degraded present one rejects is a DISCLOSURE,
since "absent may pass" is this row's first clause. (A third relation, MR-3
"degrading the PARENT must not be softer than degrading the child", was
retired: it is one ordered pair of present rungs, which MR-1 now covers.) It
extends
`_total_binding.probe_check`, which cannot reach this row for two structural
reasons: its decision is binary (no severity lattice, and no leg is ever
compared to ANOTHER leg), and its `_default_mutant` is type- and
shape-PRESERVING, so it raises `ProbeConfigError` on exactly the degenerate
mutants row 20 is about and delegates them to a hand-written predicate pattern.

WHAT IT COVERS TODAY, stated so this paragraph is not read as closure: the C18
surface, ratcheted by `tests/test_degradation_monotonicity.py` against the
verbatim pre-fix module from `a35ca9035` (7 TIER-1 witnesses of ONE defect
pre-fix; 0 post-fix, plus 1 declared limit). A sweep of `audit_bundle/plugins/`
was run and is mostly VACUOUS by the oracle's own V4 gate: 1 of 12 plugins
(`spec_sha_pin`) had a fixture that engaged it, and that one HELD. `extensions/`
beyond C18 is UNSWEPT. The row is therefore enforced on ONE surface and
unenforced on the rest — the same sentence as before with a smaller remainder,
not a closure.

**Scope, stated honestly.** In-band enforcement covers what the verifier can
see: a kit entry inside the bundle is refused, a resolved primitive sourced
inside the bundle is refused before recompute, and an anchor inside the bundle
is refused at construction and re-checked at verify time. It does NOT cover the
out-of-band channel: an operator who accepts a kit by email from the audited
party is unprotected, and `kit.py` says so. That residual is procedural by
decision (D2 declined to promote it to its own row) — it is a stated,
customer-owned precondition, exactly like vouching for the anchor.

## Residual / out-of-scope (deliberate, not silent)

- **Authority of the anchor itself.** The `SpecAnchor` is trusted as the
  auditor's distribution artifact (supplied at construction). Distributing it
  (signed allowlist vs. per-audit required-SHA vs. verifier-bundled file) is an
  operational/deployment concern, not enforced here. The mechanism this code
  provides is: *given* an anchor, the producer cannot author or select around
  it.
- **Monotone-strictness instantiation.** The as-built rule is the conservative
  reading — types sharing a `primitive_id` must carry an **identical**
  comparator (no strength variation at all). A graded partial order
  (equally-or-more-strict) is a documented future generalization; the identical
  rule is sound and strictly stronger for the substitution attack.
- **Coverage source.** Coverage is checked against the `outputs/` file
  enumeration. Outputs that exist in neither `outputs/` nor `manifest.outputs`
  (a genuinely absent output) are a cross-host / causal-chain (C19) concern, out
  of scope for this single-bundle dispatch step.
